## Formatter and allocator contracts

Global `0x01652F1C` supplies a temporary-buffer allocator:

1. virtual slot `+0x14` allocates exactly `0x400` bytes with alignment
   `0x10`;
2. virtual slot `+0x18` releases that same temporary buffer after the string
   is reconstructed.

The formatter target `0x01251E9C` is a four-argument variadic-format wrapper.
Its native wrapper forwards destination, size, format and va-list state into the
CRT formatting core with a null locale. The portable reconstruction follows
the already-established project precedent in `FUN_00401FE0` and uses
`std::vsnprintf` with the exact fixed limit `0x400`.

## Reference-counted destination contract

Argument 1 is the same one-pointer holder already recovered as
`FUN_00402360_String`.

After formatting:

1. if the destination block is non-null, decrement its leading refcount;
2. if the new count is zero, release it through global allocator
   `0x01652F28`, virtual slot `+0x18`;
3. call recovered `FUN_00402360` with the temporary C string, constructing a
   fresh reference-counted string block;
4. free the temporary `0x400` buffer through `0x01652F1C/+0x18`;
5. return the destination pointer.

The reconstruction reuses `FUN_004023E0` for the inlined release semantics
and `FUN_00402360` for the constructor semantics rather than duplicating
those already-recovered contracts.

## Tests and harness-only guards

`tests/unit/test_fun_00407c60.cpp` covers:

- no-services host guard: destination is untouched;
- temporary-allocation failure host guard: destination is untouched;
- normal variadic formatting and exact `0x400` / `0x10` scratch request;
- null/empty previous destination path;
- existing shared block: refcount decrements without free;
- existing unique block: refcount reaches zero and is released;
- fresh string construction and temporary-buffer release.

The two service/allocation guards are portable harness safety only. The native
target assumes its global allocator exists and contains no equivalent early
exit.
