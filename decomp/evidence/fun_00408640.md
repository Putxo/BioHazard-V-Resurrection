## ABI, object size, caller and early-exit evidence

A complete decoded scan of the exact `.text` section finds exactly **one**
direct rel32 call to `0x00408640`, at `0x00408929`.

The caller proves the object is exactly eight bytes and shows the native
allocation-failure early exit before construction:

~~~text

00408917  call 004085D0h
0040891C  add  esp,4
~~~

Thus 8640 itself is a no-stack-argument `thiscall`: ECX is the allocated
eight-byte object and EAX returns that same pointer. The native 8640 body has no
conditional branch or local early return. The allocation-null early exit lives
in its caller and is not incorrectly moved into the reconstructed native flow.

The executable contains no raw little-endian absolute `0x00408640` pointer
value; the observed caller reaches it through rel32 CALL.
