## ABI, layout, exceptions and helper contracts

The final `ret 0x0C` proves three 32-bit stack arguments while ECX is kept
as destination in ESI:

~~~text
FUN_004082E0_String* FUN_004082E0(
    FUN_004082E0_String& destination,
    const FUN_004082E0_String& source,
    uint32_t position,
    uint32_t count)
~~~

The SSO layout is structurally identical to the neighboring 8070 family:

- storage union at `+0x04`;
- logical length at `+0x14`;
- capacity at `+0x18`;
- capacity below `0x10` means inline storage;
- capacity at least `0x10` means the union stores a heap pointer.

The exact executable contains:
- `"invalid string position"` at VA `0x01541F84`;
- `"string too long"` at VA `0x01541F74`.

The call at `0x0125136C` is therefore the out-of-range path used when
`position > source.length`. The call at `0x0125132D` is the length-error
path reached only when the selected substring length exceeds
`0xFFFFFFFE`.

The native `FUN_00408100` dependency is invoked only when destination
capacity is smaller than the selected substring length. 82E0 passes:
- first argument: required substring length;
- second argument: current destination length.

Because 8100 is parallel work, this recovery keeps it behind an injected
growth callback rather than claiming or duplicating its allocator behavior.

The four-argument helper `0x01251A56` validates/copies:
destination pointer, destination capacity, source pointer, and byte count.
The reconstruction uses `std::memmove` after reproducing the same storage
resolution and capacity conditions.

## Behavioral reconstruction

1. If `position > source.length`, throw
   `std::out_of_range("invalid string position")`.
2. Compute `available = source.length - position`.
3. Clamp `count` to `available`.
4. If source and destination are the same object, call the 8070 erase contract
   for `[position+count,end)`, then erase `[0,position)`, and return this.
5. Reject selected length above `0xFFFFFFFE` with
   `std::length_error("string too long")`.
6. If destination capacity is insufficient, invoke the opaque 8100 growth
   contract with required length and current destination length.
7. If selected length is zero, set destination length to zero and write the
   terminator without resolving source storage.
8. Resolve source and destination storage using the exact SSO threshold.
9. Copy the selected substring.
10. Store the new destination length, append NUL, and return this.

The portable implementation reproduces the already-proven 8070 erase
semantics locally only for the self-alias branch so publication remains
link-independent. It does not modify or claim 8070.
