## Imported-call identity and synchronization gate

PE import decoding resolves:

- IAT VA `0x01371178` to `KERNEL32!EnterCriticalSection`;
- IAT VA `0x013710E8` to `KERNEL32!LeaveCriticalSection`.

This matches the already-published paired wrappers `FUN_00407B10` and
`FUN_00407B30`.

The object layout used by this routine is therefore structurally proven at
the required offsets:

- `this+0x04..this+0x1B`: opaque 0x18-byte CRITICAL_SECTION storage;
- `this+0x1C`: object-side synchronization-enable byte;
- global byte `0x016E2090`: alternate force-synchronization gate.

The native entry and exit gates are identical: if `this+0x1C` is nonzero,
the global byte is short-circuited and the import is called. Otherwise the
global byte is read and the import is called only when that byte is nonzero.

## Indexed store and ABI

After the optional EnterCriticalSection call:

1. first stack argument is loaded into ECX;
2. second stack argument is loaded into EDX;
3. ECX is multiplied by `0x5E0`;
4. EDX is stored at `this + 0x34 + index*0x5E0`;
5. the same synchronization gate optionally invokes LeaveCriticalSection;
6. the function returns with `ret 8`.

This establishes the native shape:

~~~text
void __thiscall FUN_00407DC0(
    FUN_00407DC0_Object* this,
    uint32_t index,
    uint32_t value)
~~~

The multiply/store arithmetic is 32-bit x86 arithmetic. The portable
reconstruction therefore computes the byte offset in `std::uint32_t` before
applying it to the host object.

A complete decoded direct `CALL rel32` scan of the exact `.text` image
finds **10 direct calls** to `0x00407DC0`.

Representative caller proving argument order:

~~~text
004119F0  mov edx,[esi+140h]
004119F6  mov ecx,[016E2044h]
004119FC  push edx
004119FD  push 0
~~~

Because x86 pushes arguments right-to-left, `0` is the first argument
(index) and EDX is the second argument (value). The callee's `ret 8`
confirms two 32-bit stack arguments.

A second representative caller uses dynamic values:

Here EBX is the index and EAX is the stored value.

## Recovered behavior

The original behavior is reconstructed as:

1. determine whether synchronization is enabled by `this+0x1C` or global
   byte `0x016E2090`;
2. when enabled, enter the critical section at `this+4`;
3. unconditionally write the 32-bit value at
   `this+0x34+index*0x5E0`;
4. when enabled, leave that same critical section;
5. return.

There is **no native early return before the indexed write**. The two
conditional branches bypass only the imported synchronization calls; the
store is unconditional.

The host object models two entry strides only so unit tests can safely verify
both base and nonzero-index offsets. That modeled count is not a claim about
the native container's total capacity, and no synthetic bounds check is added.

## Tests and host-only guards

`tests/unit/test_fun_00407dc0.cpp` covers:

- missing services: no invalid host callback, but the unconditional native
  store still occurs;
- missing global-reader shim with inactive object byte: synchronization is
  suppressed host-side, while the store still occurs;
- native synchronization-bypass branch when both flags are zero;
- object-active path, including short-circuiting the global read;
- global-force path when the object byte is zero;
- exact critical-section pointer `this+4`;
- exact base `0x34` and stride `0x5E0` using indices 0 and 1;
- callback ordering: Enter observes the old slot value and Leave observes the
  newly written value;
- incomplete host lock callback pair: suppress both host lock shims without
  suppressing the native store.

A standalone C++20 build and run with
`-Wall -Wextra -Wpedantic` passes before repository publication.
