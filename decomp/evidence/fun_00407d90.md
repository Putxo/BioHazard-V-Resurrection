## ABI and direct-call evidence

The `ret 8` proves two stack arguments while the entry dereferences ECX
before touching either stack argument. The first stack argument is loaded into
ESI and used as the object pointer for both delegated calls. The recovered
thiscall-style contract is therefore:

~~~text
FUN_00402360_String* FUN_00407D90(
    const FUN_00402360_String& source,
    FUN_00402360_String& destination,
    const char* suffix)
~~~

A complete GNU objdump decoded scan of the exact `.text` section finds
**16 direct CALL instructions** targeting `0x00407D90`, including
`0x0040398E -> call 0x00407D90`.

A representative caller preserves two arguments on the stack, constructs a
temporary source string, moves that returned holder to ECX, and then invokes
D90. Chained call sites at `0x005E05DD`, `0x005E05E4`,
`0x005E05EB`, and `0x005E05F2` immediately move each returned EAX back
into ECX for the next D90 call, independently confirming that D90 returns the
destination holder.

A whole-file raw little-endian pointer scan finds zero embedded data pointers
to `0x00407D90`; the decoded call references are the relevant entry evidence.

## Recovered behavior

1. Read the source block pointer from `this`.
2. If non-null, use its payload at block+8.
3. If null, use the fixed empty literal at `0x0137AA5C`.
4. Construct the supplied destination from that C string through already
   recovered `FUN_00402360`.
5. Pass the second stack argument to already recovered `FUN_00407D10`,
   appending the suffix to the newly constructed destination.
6. Return the destination pointer.

This is a copy-then-append wrapper over existing recovered string primitives;
no allocator, concatenate helper, or reference-count implementation is
duplicated in D90.
