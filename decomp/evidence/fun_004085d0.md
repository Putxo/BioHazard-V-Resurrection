## ABI and allocator contract

The wrapper reads one 32-bit stack argument and ends with a plain `ret`.
Every decoded direct caller removes exactly four bytes after the call:

~~~text
push size
call 004085D0
add  esp,4
~~~

The recovered ABI is therefore:

~~~text
void* __cdecl FUN_004085D0(uint32_t size)
~~~

The native helper:

1. loads allocator owner global `0x01641A0C`;
2. loads its vtable;
3. selects virtual slot `+0x14`;
4. pushes fixed alignment `0x10`;
5. pushes the caller-supplied size unchanged;
6. invokes the allocator virtual method with the owner still in ECX;
7. returns the allocator result unchanged.

This exact allocator shape is independently documented throughout the
repository. For example, the factory cluster evidence uses the same global
`0x01641A0C`, virtual slot `+0x14`, and alignment `0x10`. The older
recovered allocation thunk `FUN_00402120` has the same instruction shape
against allocator global `0x01641AA8`, providing a validated portable seam
precedent.
