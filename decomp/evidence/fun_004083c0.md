## ABI and SSO layout

The final `ret 8` proves two 32-bit stack arguments while ECX is retained as
the destination string:

~~~text
FUN_004082E0_String* FUN_004083C0(
    FUN_004082E0_String& destination,
    const char* source,
    uint32_t count)
~~~

The object layout is the same neighboring SSO string already recovered by
82E0:

- storage union at `+0x04`;
- logical length at `+0x14`;
- capacity at `+0x18`;
- capacity below `0x10` means inline storage;
- capacity at least `0x10` means the union contains a heap pointer.

## Behavioral reconstruction

1. Resolve the current destination data pointer according to the SSO threshold.
2. Test whether `source` lies in the half-open interval
   `[data, data + length)`.
3. If it does, convert `source` to an offset and delegate to
   `FUN_004082E0(destination, destination, offset, count)`.
4. Otherwise reject `count > 0xFFFFFFFE` through the same
   `0x0125132D` / `"string too long"` path proven for 82E0.
5. If destination capacity is smaller than `count`, call
   `FUN_00408100` with required length = `count` and preserved length =
   current destination length.
6. If `count == 0`, set logical length to zero, write the terminator, and
   return without dereferencing `source`.
7. Resolve destination storage, copy exactly `count` bytes from the external
   source through the checked-copy helper `0x01251A56`, store the new length,
   append NUL, and return this.

The order is significant: self-alias detection happens before the length
limit. Therefore an internal source plus `count == UINT32_MAX` delegates to
82E0 and is clamped to the available substring instead of throwing.
