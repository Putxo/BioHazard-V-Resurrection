## ABI and direct-call evidence

The final ret 4 proves one stack argument, while ECX is preserved as the object
pointer in ESI. The recovered portable signature is therefore a thiscall-style
append operation over the same one-pointer holder used by FUN_00402360:

~~~text
void FUN_00407D10(FUN_00402360_String& destination, const char* suffix)
~~~

A complete decoded scan of the exact .text section finds 75 direct CALL
instructions targeting 0x00407D10.

Representative caller 0x00403713 constructs a local string holder and then
calls 0x00407D10 repeatedly with literals/runtime strings. The instruction
after each call reloads unrelated state instead of consuming EAX. Additional
callers show the same pattern, so no source-level return value is asserted.

The next aligned function at 0x00407D90 provides an independent contract
cross-check: it constructs a destination from one string and calls 0x00407D10
with its second argument before explicitly returning the destination itself.

## Temporary construction and append behavior

1. Construct a temporary reference-counted string from suffix through the
   already-recovered FUN_00402360.
2. If that temporary is null, return immediately with destination untouched.
   This covers the native null/empty suffix path.
3. If destination is null, adopt the temporary pointer and increment its
   leading refcount.
4. Otherwise call native helper 0x01199FB0 with old and temporary blocks.
5. Release the old destination block by decrementing its leading refcount and
   dispatching allocator 0x01652F28 virtual slot +0x18 only when it reaches
   zero.
6. Install the combined block returned by 0x01199FB0.
7. Release the temporary suffix block with the same refcount/free contract.

The increment in the empty-destination branch is balanced by step 7, leaving
the adopted destination with one live reference.

## Native helper 0x01199FB0 contract

The helper is outside this assigned function and is therefore represented by
an injected opaque service instead of being claimed as recovered here. Its
exact native body independently shows:

- old length from old+0x04 plus new length from new+0x04;
- allocate total_length + 0x0C bytes with alignment 0x10;
- initialize new block refcount to 1 and length to the sum;
- copy old payload first, then new payload;
- append a terminating NUL;
- return the new block pointer.

The portable concatenate callback preserves this observed input/output
contract while keeping recovery scope exclusive to FUN_00407D10.
