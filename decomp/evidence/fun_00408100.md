## Object layout and growth policy

The accessed layout is a 28-byte SSO-style string object:

- this+0x00..0x03: opaque leading dword;
- this+0x04..0x13: 16-byte storage union;
- this+0x14: current string size;
- this+0x18: current capacity;
- capacity below 16 selects inline storage at this+4;
- capacity 16 or greater selects the heap pointer stored at this+4.

The portable host stores its native-width test pointer inside that opaque
16-byte union while preserving the target offsets exactly.

The native capacity policy is:

~~~text
candidate = requested_capacity | 0x0F
if candidate > 0xFFFFFFFE:
    new_capacity = requested_capacity
else:
    half = old_capacity >> 1
    # multiply by 0xAAAAAAAB, take high half, then >> 1
    # equals floor(candidate / 3)
    if floor(candidate / 3) < half
       and old_capacity <= 0xFFFFFFFE - half:
        new_capacity = old_capacity + half
    else:
        new_capacity = candidate
~~~

The first allocation is new_capacity + 1 through recovered FUN_00407E70,
which delegates to validated FUN_00407A90.

After successful allocation the function:

1. copies preserved_size bytes from the current inline/heap data only when
   preserved_size > 0;
2. frees the old heap buffer when old capacity is at least 16;
3. installs the new pointer at this+4;
4. writes new capacity to this+0x18;
5. writes preserved_size to this+0x14;
6. writes a trailing NUL at data[preserved_size].
