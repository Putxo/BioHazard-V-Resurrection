# FUN_00405BD0 evidence

- VA: `0x00405BD0`
- RVA: `0x00005BD0`
- V6 candidate size: `544` bytes, ending at the next candidate `0x00405DF0`.
- The recovered body returns with plain `ret` at `0x00405DE4`; `0x00405DE5..0x00405DEF` is `INT3` padding.
- Calling convention: cdecl-style single stack argument. After local/register pushes, the argument is read at `0x00405C0C` from `[esp + 0x21C]`.
- Direct callers at `0x004064A3`, `0x00406C83`, and `0x00407230` push an integer loop value spanning `0..10`; the caller at `0x0050991F` also pushes a dword value. The host reconstruction therefore models the argument as `std::uint32_t message_index`.

## Instruction evidence

- `0x00405BD0..0x00405BED` reads global object `0x0165BBB0`, computes the current per-slot offset with stride `0x8C74`, and saves the existing dword at slot `+0x70`.
- `0x00405BEE..0x00405C35` conditionally enters/leaves the object's critical section around replacing that slot with the stack argument. IAT `0x01371178` resolves to `KERNEL32!EnterCriticalSection`; IAT `0x013710E8` resolves to `KERNEL32!LeaveCriticalSection`.
- `0x00405C35..0x00405C41` saves byte `0x016E1D3C + 0x904D` and forces it to `1`.
- `0x00405C48..0x00405C63` resolves literal `Image\\Archive\\MsgResource` through `0x004E99F0` and copies the returned path with format literal `%s`.
- `0x00405C68..0x00405C98` selects the global string at `0x016E1D3C + 0x102C` (falling back to empty literal `0x0137AA5C`) and formats a second local path with literal `%s\\%s.arc` at `0x0137AAD4`.
- `0x00405C9D..0x00405CF5` gates a special archive path on bit `0x00200000` of `[0x016E1660 + 0x1E550]`: it prepares the archive through `0x0119B710`, registers the primary path through `0x00D14C10` with key object `0x016E216C`, finalizes non-null results through `0x00D25060`, then checks the archive path through `0x0119B910`.
- The conditional branch at `0x00405CF5` jumps directly to cleanup at `0x00405D75` when that check returns true. This is the observed early batch-skip path; it does **not** bypass state restoration.
- `0x00405CF7..0x00405D04` starts the normal batch through `0x00A52D90` and `0x00A54010`.
- `0x00405D09..0x00405D69` walks exactly `0x48 / 8 = 9` table records from `0x01567500`. For each record it resolves the first field through `0x004E99F0`, registers through `0x00D14C10` using the second-field key object, and conditionally binds non-null results through `0x005477E0` when suppressor bytes `0x016B1F39` and `0x016B1F3B` are both clear.

- `0x00405D6B..0x00405D72` ends the batch through `0x00A54120` with argument `0`.
- `0x00405D75..0x00405DC9` restores the saved loading byte and the saved per-slot dword, using the same conditional critical-section path for the latter.
- `0x00405DC9..0x00405DDE` emits marker `0x0137AF90` through `0x01198F40`, unwinds the local frame, and returns.

The target executable used for this evidence is the repository-documented RE5DX9 1.1.0 Dev Release with SHA-256 `323d1aabccc74505745588097e2b298b14e114393bfc24f6830e98b658e67815`; the executable itself is not stored in the repository.

## Host reconstruction

The host implementation models the machine routine as a temporary message-context swap plus a message-resource registration batch. `exchange_message_index` is the service seam for the critical-section-protected slot replacement/restoration, while `exchange_global_loading` preserves the exact prior loading flag rather than assuming it was false. The archive-special early branch is represented as a batch skip so cleanup always executes. The nine table entries and their order are reconstructed from the exact target table; engine-specific registry, archive, and bind operations remain injectable service callbacks.
