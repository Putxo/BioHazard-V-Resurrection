## Calling convention and arguments

Representative wrapper at `0x004064E0` loads a dynamic first argument and pushes, in reverse cdecl order:

1. `7`

The callee reads the six original arguments at:

- second: `0x00406249` / `0x00406269`

- sixth: `0x00406391`

The first argument is signed: `0x0040622C` uses a signed negative test before calling `0x00407E10`, and wrapper `0x00406570` passes `-1`. The looped caller at `0x00406CA0` supplies values `0..10`.

- For a non-negative first argument, `0x00406249..0x00406257` passes argument 2 through `0x004E99F0` and formats the returned text with `%s` (`0x0137B518`).

## Batch and first table

Normal flow calls `0x00A52D90(primary_path)` at `0x00406314..0x00406319` and `0x00A54010()` at `0x00406321`.

Argument 3 is the first table pointer and argument 4 is a signed count:

- null pointer skips the loop (`0x00406326..0x0040632F`)
- count `<= 0` skips the loop (`0x00406331..0x0040633A`)
- records advance by exactly 8 bytes
- record field 0 is passed directly as the path/token to `0x00D14C10`
- record field 1 is passed as its opaque key/address
- enabled flag is `1`

The returned registration is bound through `0x005477E0` only when both suppressor bytes `0x016B1F39` and `0x016B1F3B` are clear and the return value is non-null.

Caller table `0x01567590`, for example, contains 15 eight-byte records such as a path pointer for `stage\\game` paired with `0x016E2758`, confirming the `{path/token, key/address}` structural interpretation without assigning an unsupported higher-level type to the second field.

## Second, resolved table

Argument 5 is a second 8-byte-record table and argument 6 is a signed count:

- null pointer skips the loop (`0x00406386..0x0040638F`)
- count `<= 0` skips the loop (`0x00406391..0x0040639A`)
- `0x004063A0..0x004063B1` resolves record field 0 through `0x004E9B90`
- the resolved path, record field 1, and enabled flag `1` are then passed to `0x00D14C10`
- the same two suppressor bytes and non-null result gate the `0x005477E0` binding call

`0x004E9B90` consumes exactly one stack argument and returns with `ret 4`; the nearby `push 1` belongs to the later registration call, not to the resolver. This distinguishes the second table's resolver from an imagined two-argument API.

Normal completion calls `0x00A54120(0)` at `0x004063F5..0x004063FC`.
