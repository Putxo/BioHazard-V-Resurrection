## RTTI-proven class identity

The vtable written at `0x00408565` is `0x01541F54`. Its MSVC complete
object locator resolves to type descriptor:

~~~text

~~~

The base-copy helper first installs vtable `0x01541FAC`, whose RTTI type
descriptor is:

~~~text

~~~

Thus 8550 is the `std::logic_error` copy-construction layer over a copied
`std::exception` base plus an embedded SSO message.

The single decoded direct caller at `0x012513B2` calls 8550 and immediately
overwrites the returned object's vtable with `0x01541F6C`. RTTI resolves
that derived vtable to:

~~~text
.?AVout_of_range@std@@
~~~

This independently confirms the copy-constructor role in the logic_error
hierarchy.

host-only guard equivalent to a null duplication result; it does **not**
create an early return.

## Object layout and derived-message copy

8550 reuses the already recovered `FUN_00408490_Object` layout:

~~~text

+0x04  base_message
+0x08  base_owns_message
+0x0C  FUN_004082E0_String message
~~~

After the base copy, 8550:

1. installs final `std::logic_error` vtable `0x01541F54`;
2. addresses the embedded string at `this+0x0C`;
3. sets embedded length to zero;
4. sets embedded capacity to 15;
5. writes the first inline byte to NUL;
6. calls recovered
   `FUN_004082E0(message, source.message, 0, UINT32_MAX)`;
7. returns `this`.

The embedded string's allocator-state dword at object `+0x0C` is not
written by 8550 and is intentionally preserved.
